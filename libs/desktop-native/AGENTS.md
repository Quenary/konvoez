# Desktop Native Agent Guide

Rules for `libs/desktop-native` — the Rust native module of the Konvoez desktop client (per-application audio capture, global key hook). General rules (scope, tests, checks) are in the root `AGENTS.md`. The Electron side is in `apps/desktop`.

## Stack

- **Rust** pinned by the root `rust-toolchain.toml` (channel, `clippy`, `rustfmt`, targets). Do not override the toolchain locally or in CI.
- **napi-rs 3** (`napi`, `napi-derive`, `@napi-rs/cli`) builds one `konvoez-native.<triple>.node`.
- Windows: **`windows`** crate (WASAPI process loopback, `WH_KEYBOARD_LL`). Linux: **`pipewire`** / **`libspa`** (audio), **`x11rb`** (XRecord key hook).
- Targets: `x86_64-pc-windows-msvc`, `x86_64-unknown-linux-gnu`.

## Layout

```
src/
  lib.rs        # napi exports only: thin wrappers, no platform logic
  audio/        # mod.rs (shared types, mixing) + windows.rs, linux.rs
  input/        # mod.rs (shared types, key-code map) + windows.rs, linux.rs
```

- Platform code lives behind `#[cfg(target_os = "...")]` in its own file. Every module compiles on every target; unsupported platforms return `is_supported() == false`, never a build error.
- Shared, platform-independent logic (format conversion, mixing, key-code mapping, id parsing) goes in `mod.rs` or a plain module so it is unit-tested on any OS.

## napi boundary

- The JS API is small and stable: `is_*_supported()`, `start_*(options, callback) -> Handle`, `handle.stop()`. Keep TS types generated by `napi build` in sync and consume them only through `apps/desktop/src/main/native.ts`.
- Use `#[napi(object)]` structs and string enums for options/results; do not pass untyped `JsObject` around.
- Native threads call JS only through `ThreadsafeFunction` (non-blocking mode). Never touch `Env` or JS values off the main thread.
- Pass PCM as `Float32Array`/`Buffer` chunks; do not serialize audio to JSON.
- Errors cross the boundary as `napi::Error` with a short message. Inside the crate use `Result` and `?`; define error types with `thiserror` only if a module needs more than a string.

## Rust conventions

- No `unwrap()` / `expect()` / `panic!` in runtime paths; a panic in a native thread can kill Electron. Tests may unwrap.
- `unsafe` only for FFI calls, in the smallest possible block, each with a `// SAFETY:` comment. Wrap OS handles in RAII types that release them in `Drop` (COM objects, hooks, PipeWire streams).
- Every background thread has an owner (`Handle`) and a stop signal; `stop()` is idempotent, joins the thread, and is also called from `Drop`. No detached threads. The only exception is the key hook thread: the X11 RECORD loop can block on a stuck server, so `KeyHookHandle::stop()` waits up to a second and then leaves that thread detached rather than freezing Electron.
- Real-time audio callbacks do not allocate, lock contended mutexes, log, or call into JS; they push into a preallocated buffer, and a separate thread delivers chunks.
- Prefer `std` sync primitives and channels; do not add an async runtime.
- Keep dependencies minimal, with `~` ranges and only the crate features actually used (e.g. explicit `windows` features).
- Never change system volume, default devices, or audio routing; capture only. The global key hook must always pass events on (`CallNextHookEx`) and never swallow keys.
- Log through the `log` facade at most; user-facing errors are reported by the TS side.

## Checks

Run before finishing (also wired as Nx targets `desktop-native:{build,test,lint}`):

```
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
npx nx run desktop-native:build
```

## Testing

- `cargo test` for pure logic (conversion, mixing, ring buffers, key-code tables, id parsing). Platform capture and hooks are verified manually; keep them thin so that most logic is testable.
- The TS fallback paths (`native.ts` returning `null`) are covered by Vitest in `apps/desktop`.
